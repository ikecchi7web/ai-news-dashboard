11/4〜11/6朝の日本語記事から、使い方・手順・プロンプト中心に厳選（日本時間）
  1. 1

    Claude CodeからCodexを呼ぶなら、いまはcodex exec（Skill/Bash）が実務向き

    最新のCodex CLIではmcp-serverが消え、MCP接続は古い版に戻さないと失敗します。レビューならcodex exec -s read-only、実装なら-s workspace-writeでモデルとeffortを固定する手順が実機比較で推奨されています。

    ララテックlaratech.jp →
  2. 2

    MCPとSkill/Bashの使い分け　長時間タスクはSkill、CRUDはMCP

    Claude CodeからCodexを動かすとき、MCPは進捗が見えにくく重く、Skillからcodex execを叩くほうが軽いという比較です。カレンダーやDBなどすぐ返るCRUDはMCP、コード生成など長い作業はSkill/Bash、という整理が使いやすいです。

    とつブログm-totsu.com →
  3. 3

    公式ガイド：Skillsは「いつ使うか」をdescriptionに書き、手順は本文へ

    Anthropicの日本語ドキュメントで、SKILL.mdの作り方と動的コンテキスト（!`git diff`など）を解説しています。同じ指示を何度も貼る・CLAUDE.mdが手順で肥大化したときに切り出す、という判断基準がはっきりします。

    Claude Docscode.claude.com →
  4. 4

    Skill → CLI → MCP → Plugin　迷ったら軽い順に当てる

    手順はSkill、外のデータはまずCLIをSkillから呼び、毎日深く使う外部連携だけMCP、まとめて配るならPlugin、という判断軸のQiita記事です。「統計をSkillに書いたら取れなかった」という失敗例から、層の取り違えを防ぐチェックリストになっています。

    Qiitaqiita.com →
  5. 5

    「スキルでよくない？」への答え　SDKなしでMCPサーバーを書く手順

    スキルは手順書、MCPはClaudeが書き換えられないツール、という違いをリクエストの中身で示し、Node.jsだけで動くメモMCPの全文とclaude mcp addまで載せています。許可や長い結果の扱いなど、作ったあとのつまずきどころも具体的です。

    Zennzenn.dev →
